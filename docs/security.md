# Security and privacy

This page describes what the stack exposes, what protects it, and where speech and text go. It describes the code in
this repository. It is not a security audit. Review it against your own requirements before a real event.

## What is public

| Endpoint | Open to | Why | Protection |
|---|---|---|---|
| Listener page (CloudFront, HTTPS) | Anyone with the URL | Attendees open it on their phones. | Static files in a private S3 bucket (Origin Access Control), HTTPS only, security response headers. |
| `/token` (CloudFront to Lambda function URL) | Anyone with the URL | The page needs a token to join the room. | The function URL requires IAM auth, so only CloudFront can call it. The Lambda issues **subscribe-only** tokens. |
| LiveKit host: TCP 443, TCP 7881, UDP 50000-60000 | Internet | Browsers anywhere must reach signaling and media. | A token is required to join. Port 7880 (plain signaling), 22 and 80 are not open. TLS ends in Caddy (Let's Encrypt). |
| SRT ingest: UDP 9000 on the Network Load Balancer | **Venue IP only** | OBS sends the audio here. | Security groups on the load balancer and the task allow only `venueCidr`. SRT passphrase (AES). |

Anyone who has the listener URL can listen. There is no login. Do not publish the URL if the content is not public.

## Tokens

- The Lambda mints a LiveKit token with `canPublish=false` and `canPublishData=false`, a random identity, and the
  configured room only (`cdk/lambda/token/`). Nothing in the request changes the grant.
- Listener tokens expire after `listenerTokenTtlSec` (default 21600 s, 6 hours). A listener must reload the page after
  that. The app's publisher token has its own lifetime (`publisherTokenTtl`, default 6 h).
- The token endpoint accepts `GET` and `HEAD` only.

## Secrets

- The LiveKit API key and secret and the SRT passphrase are generated by Secrets Manager. The CloudFormation template
  contains only their ARNs.
- ECS injects them into the app container as environment variables through the task execution role. The LiveKit host
  reads its secret at boot with its instance role. The boot script does not print it. The token Lambda reads it with
  its function role.
- Nothing in the repository holds a secret. `scripts/check-publishable.mjs` scans for keys and account IDs before a release.
- Get the SRT passphrase with the `GetSrtPassphraseCommand` stack output. Treat it like a password and do not paste it
  into chat or tickets. To rotate it, rotate the secret in Secrets Manager, restart the app task (`--force-new-deployment`) and
  update the encoder.

## Least-privilege IAM

| Role | Allowed |
|---|---|
| App task role | `transcribe:StartStreamTranscription`, `translate:TranslateText`, `polly:SynthesizeSpeech` (these actions have no useful resource scoping). With `translateEngine=llm` also `bedrock:InvokeModel` on the one inference profile and its destination foundation models in `ap-northeast-1` and `ap-northeast-3`, and `translate:GetTerminology` on one terminology. |
| LiveKit instance role | `AmazonSSMManagedInstanceCore` (shell access through Systems Manager, no SSH), read of the LiveKit secret, write to its log group. IMDSv2 is required. The disk is encrypted. |
| Token Lambda | Read of the LiveKit secret, write to its log group. |

The Fargate task and the LiveKit host sit in public subnets without a NAT gateway. Security groups are the boundary:
the app accepts SRT and the health check from the load balancer only.

## Transcript privacy and data flow

```
venue audio --SRT--> Fargate app --audio--> Amazon Transcribe  (English text)
                         |--- text --------> Amazon Translate or Amazon Bedrock (Japanese text)
                         |--- text --------> Amazon Polly      (Japanese speech)
                         '--- speech ------> LiveKit host --WebRTC--> listeners
```

| Data | Goes to | Stored by this project |
|---|---|---|
| Venue audio | Transcribe streaming | No. The app keeps no recording. |
| English text | Translate or Bedrock (and the logs) | **Yes, in CloudWatch Logs** (see below). |
| Japanese text | Polly (and the logs) | **Yes, in CloudWatch Logs.** |
| Japanese speech | LiveKit, then listeners' browsers | No. LiveKit does not record in this setup. |

- The app logs the English and Japanese text of every chunk (`COMMIT`, `SYNTH`, `FAILED` lines). Anyone who can read the
  log group can read the transcript. The default retention is 14 days (`logRetentionDays`). Lower it, or restrict
  access to the log group, if the content is confidential.
- The Bedrock model runs through a `jp.` cross-Region inference profile. Its requests are processed in the Japan Regions
  (Tokyo and Osaka) listed in the IAM policy.
- For how each AWS service handles content (storage, use for service improvement, opt-out), read the current AWS
  documentation and terms for Amazon Transcribe, Translate, Polly and Bedrock. They can change, so this repository does not
  copy them. Check them against your data-protection rules before you process confidential talks.
- The end-to-end test harness (`e2e/`) does record the translated audio and the logs of its own runs into `e2e/runs/`
  (git-ignored). Treat those folders as confidential if the source audio is.

## Machine-translation disclaimer for the listener page

Show a short notice on the page. The current page does not include one. Suggested text:

> This is a machine translation. Speech is transcribed, translated and spoken by software, so it can be late or wrong.
> It is not an official interpretation. Please do not rely on it for legal, medical or safety decisions.
> 
> この音声は自動翻訳です。音声認識・機械翻訳・音声合成によって生成されるため、遅れや誤訳が生じることがあります。公式な通訳ではありません。法律・医療・安全に関わる判断には使用しないでください。

Add it to `app/web/index.html`.

## Recording and consent

- The system does not record the event. The logs hold text. If you also record the room, the stream or the
  translated audio, tell the speakers and the audience beforehand and follow the law and the venue rules that apply
  to you.
- Tell speakers that their speech is sent to AWS services for transcription, translation and speech synthesis, and that
  the text is kept in logs for the retention period.
- Questions from the audience are processed too. Say so when you take questions.
- The synthetic voice is not the speaker's voice. Avoid wording that suggests the speaker said the Japanese words.
